    Differential Expression¶

    This page documents Splyne's differential expression post-processing module.

    Purpose¶

    The differential expression module runs a dedicated Nextflow workflow around an R/Quarto analysis script for count-based expression analysis. It is not a nf-core workflow but a custom-developed analytical script following conventional procedures, with DESeq2 R package for gene-level differential expression analysis and clusterProfiler for gene-set enrichment analysis.

    The workflow has been specifically designed to leverage the raw gene-level count matrices generated by Salmon within the nf-core/rnasplice pipeline. Thereby, the expected user behaviour is:

    • Run a differential splicing analysis.
    • Retrieve the tximport/salmon.merged.gene_counts.tsv file from the pipeline results directory.
    • Prepare a dedicated metadata table in tab-separated values (tsv) format.
    • Execute the current module.

    In any case, the workflow accepts any gene-level count matrix following the input structure described below. Therefore, users may also provide count matrices generated with alternative quantification or counting tools, provided that the matrix format remains compatible with the expected input specification.

    Prerequisites¶

    • A gene count table must be available.
    • A metadata table should be created accordingly.
    • Both tables must refer to the same samples to be compatible.
    • The selected dependency profile must support the R/Quarto workflow.

    Inputs¶

    Users upload:

    • gene count table
    • metadata table

    Accepted file extensions:

    • .tsv
    • .csv
    • .txt

    Splyne stores normalized working copies under:

    temp_files/nf-dea-temp/data/

    Input stucture¶

    Gene counts matrix¶

    ensembl_gene_id sample_1 sample_2 ... sample_n
    ENSG00000000013.6 1 0 ... 2
    ENSG00000003341.6 10 14 ... 31
    ... ... ... ... ...
    ENSG00000024452.6 110 141 ... 200

    Metadata table¶

    sample condition
    sample_1 treatment
    sample_2 control
    ... ...
    sample_n treatment

    Warning

    Be aware that encoding issues may arise when sample names contain complex or special characters. It is recommended to minimize the use of special characters as much as possible.

    Configuration¶

    Advanced options expose common statistical thresholds:

    • CPM filtering threshold
    • minimum number of samples
    • adjusted significance threshold
    • log fold-change threshold

    Parameters¶

    UI parameter Pipeline argument or internal variable Default Possible values Consequence
    Dependency profile -profile apptainer apptainer, docker Selects the dependency backend used by the differential expression Nextflow workflow.
    CPM threshold SPLYNE_CPM_THR environment variable 1.0 Decimal from 0.0 to 10.0, step 0.1 Minimum counts-per-million expression required for a gene to be retained. Higher values remove more low-expression genes.
    Minimum samples threshold SPLYNE_NSAMPLES_THR environment variable 2 Integer from 1 to 100 Minimum number of samples in which each gene must be expressed. Higher values make expression filtering more stringent.
    Error rate limit SPLYNE_ALPHA_THR environment variable 0.05 Decimal from 0.00 to 0.10, step 0.01 Statistical significance cutoff used by the analysis script. Lower values reduce false positives but may reduce sensitivity.
    Log2 fold-change threshold SPLYNE_LOGFC_THR environment variable 1.5 Decimal from 0.0 to 5.0, step 0.1 Minimum effect size required for a result to be considered biologically meaningful. Higher values focus on larger expression changes.

    Execution¶

    Splyne builds the nextflow run differential_expression.nf command and submits it through the shared job manager as a declarative Workflow instance.

    The process is monitored in the same way as the nf-core workflow pages. When the run completes, selected outputs are archived for Run History.

    Outputs¶

    Outputs are generated by the dedicated Nextflow workflow and include:

    • Quality control and exploratory analysis
    • Expression filtering and normalization
    • Principal component analysis (PCA)
    • Differential gene expression analysis
    • DEA visualization through volcano plots and heatmaps
    • Gene Ontology (GO) enrichment analysis
    • MSigDB Hallmark pathway enrichment analysis

    See Results > Filtering logic for more information on ouput filtration.

    Notes and Limitations¶

    The module assumes that count and metadata tables have compatible sample definitions. It checks dimensions before execution, but users remain responsible for ensuring that sample names and experimental groups are biologically correct.
