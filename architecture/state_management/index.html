    State Management¶

    Splyne combines two complementary state mechanisms:

    • Streamlit session state for interactive, per-browser-session continuity.
    • A disk-backed run registry for recovering long-running processes after the UI is refreshed or restarted.

    Most UI state lives in st.session_state. This object behaves like a mutable dictionary that persists across Streamlit reruns for the same user session. Since Streamlit re-executes the active script after most interactions, Splyne uses session state as the contract between pages: the input page records which files are ready, workflow pages check those flags before enabling analysis, and the sidebar reads the active process state to disable unsafe actions while a command is running.

    Session state is intentionally treated as runtime state, not as permanent storage. Values can be cleared by the app reset action, by selecting a new input directory, or by restarting the browser session. Anything that must survive beyond the Streamlit session is stored on disk, either as files under temp_files/ or as active-run metadata in the run registry.

    State Categories¶

    Splyne uses session state for four main concerns:

    • Input progression: selected directory, detected reads, compression status, ready files and samplesheet status.
    • Execution control: the single active long-running process stored in job_state.
    • Workflow UI memory: working directory selections, preprocessing flags and toast suppression flags.
    • Widget state: explicit Streamlit widget keys such as data editors and per-run action buttons.

    The tables below list the explicit session-state keys used by Splyne. Streamlit may also create internal widget identifiers for widgets that do not define a custom key; those implementation-generated keys are not part of the application contract.

    Application Shell¶

    These keys are initialized by splyne_app.py and are available from the main application frame.

    Key Initial value Type Purpose
    job_state job-manager default dictionary dict Single active process state shared across pages and the sidebar.
    screen_mode sidebar str Navigation layout selected by the user: sidebar, top or hidden.
    previous_run_toast_shown False bool Prevents repeated previous-run recovery notifications during reruns.

    The app reset button calls st.session_state.clear(), removes selected temporary analysis files, and reruns the app. Reset controls are disabled while job_state["state"] is not idle.

    Input State¶

    The input page (file_loading.py) owns the state that gates all downstream workflows. It initializes the keys below through a default banner dictionary and updates them as the user selects a directory, files are detected, FASTQ files are compressed, and the samplesheet is generated.

    Key Initial value Type Updated by Purpose
    dir_path None str \| None Directory selector Absolute or user-selected path containing input read files.
    read_files None list[str] \| None Read detection File names detected in dir_path with supported read extensions.
    reads_scanned False bool Read detection Marks that the selected directory has already been scanned.
    fastq_gz_done False bool Compression step Marks that FASTQ inputs are already gzip-compressed or did not need compression.
    gz_paths None list[str] \| None Input defaults Reserved top-level placeholder for compressed FASTQ paths. The active compression process also stores gz_paths inside job_state.
    all_reads None tuple[str, ...] \| None Compression step Complete set of available read paths used as selectable values in samplesheet editors.
    ready_files None tuple[str, ...] \| list[str] \| None Compression and samplesheet editing Current input files accepted for downstream workflows. Can be narrowed after samplesheet edits.
    file_type None str \| None Samplesheet creation Detected input family used to decide samplesheet columns and validation rules.
    samplesheet_ready False bool Samplesheet creation Signals that temp_files/samplesheet.csv exists and downstream pages can proceed.

    Downstream pages use the pair below as their main guard:

    upload_correct = (
    st.session_state.get("ready_files", False)
    and st.session_state.get("samplesheet_ready", False)
)

    If this guard fails, the page stops before exposing workflow controls. This prevents workflows from launching without a validated input set.

    Preprocessing State¶

    read_trimming.py adds flags that describe the optional FASTQ preprocessing stage.

    Key Initial value Type Purpose
    ss_fastp False bool Tracks whether the clean samplesheet has been produced after fastp trimming.

    Workflow State¶

    Workflow pages share a small set of session-state keys for working directory selection and one-time notifications.

    Module Key Initial value Type Purpose
    nf-core-demo.py wd_path None str \| None Selected Nextflow working directory for QC/demo execution.
    rnafusion.py wd_path None str \| None Selected Nextflow working directory for RNA fusion execution.
    rnasplice.py wd_path None str \| None Selected Nextflow working directory for RNA splicing execution.
    rnasplice.py bt_toast False bool Suppresses repeated BAM/BAI-related warning toasts.
    rnavar.py wd_path None str \| None Selected Nextflow working directory for RNA variant calling execution.
    rnavar.py br_toast False bool Suppresses repeated BAM-readiness warning toasts.
    rnavar.py annot_toast False bool Suppresses repeated annotation-cache warning toasts.

    wd_path is reused by several workflow pages under the same key name. This means the last selected working directory can be carried between those pages during the same Streamlit session.

    Job State¶

    The active process manager is stored as a nested dictionary in st.session_state.job_state. It is initialized by py_scripts/job_manager.py and read or updated by workflow pages, the input compression step and the sidebar.

    Field Initial value Type Purpose
    state idle str Process lifecycle state: idle, running, done or archiving.
    pipeline None str \| None Name of the active workflow or utility process.
    pid None int \| None Operating-system process identifier.
    process None subprocess.Popen \| None Live subprocess object monitored across reruns.
    returncode None int \| None Process exit code once available.
    workdir None Path \| None Nextflow work directory used by the active workflow.
    resultsdir None Path \| None Directory containing workflow outputs.
    ft_path None Path \| None File containing output extensions used by the result archiver.
    zip_launched False bool Archive-launch guard for completed workflow processes.
    runid None str \| None Generated run identifier used by the run registry and ZIP filename.
    gz_paths not present by default list[str] Temporary field used only by the pigz_compression input utility process.

    job_state is deliberately single-job. When state is not idle, launch buttons and reset actions are disabled or redirected so that only one long-running process is controlled by the session at a time. See Job Manager for the full lifecycle and archiving behavior.

    Widget State¶

    Some Streamlit widgets use explicit keys. These keys are managed by Streamlit and may appear in st.session_state, but they should be treated as UI widget state rather than business logic.

    Module Key or pattern Widget Purpose
    Workflow pages wd_selector st.form Form state for selecting the workflow work directory.
    dea_postprocessing.py gc_editor st.data_editor Display state for the gene-counts table preview.
    dea_postprocessing.py metadata_editor st.data_editor Editable metadata table state.
    run_history.py download_<run_id> st.download_button Per-run stored-results download button state.
    run_history.py erase_<run_id> st.button Per-run stored-results deletion button state.

    Persistent State¶

    Session state is not sufficient for process recovery because it disappears when the Streamlit session is lost. For long-running workflows, Splyne writes active-run metadata under temp_files/app_state/ through the run registry. The registry stores the run ID, process ID, pipeline name, work directory, results directory and log paths needed by the recovery inspector.

    This disk state is only used when interactive session state cannot be trusted, such as after an application restart. Normal workflow execution still uses st.session_state.job_state as the primary runtime source of truth.

    Reset Behavior¶

    Splyne has two reset patterns:

    • Input reset: selecting a new input directory refreshes the input defaults and replaces dir_path.
    • Application reset: the sidebar reset action clears all session-state keys, removes selected temporary files and reruns the app.

    Caution

    Resetting the application should not be used while a workflow is running. The UI disables reset controls when a long-running process is active.
